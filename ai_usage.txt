## `src/compiler.py`

Four new pieces between `SemanticChecker` and `CodeGenerator`, so the pass sits exactly where the task wants it: after the checker accepts the program, before code generation.

**`contains_call(value)`** answers one question: can evaluating this value print or read? It returns true for a `CallNode` or a `MemberCallNode` and recurses into `BinOp`, `Not`, `ResultField` and `InitList`. This is the whole Task 1 safety rule in one function.

**`UseCounter`** is the one visitor. It walks the tree and builds two tables keyed by `id(node)`:

- `reads[id(decl)]`, how many reads resolve to that declaration
- `calls[id(fn)]`, how many calls name that function

The `id()` keys matter: two declarations both named `x` are two different objects, so the outer `x` cannot collect the inner `x`'s read. The counts come from the links the checker already filled, so no name lookup happens in the pass.

What counts as a read: `VarNode` (`node.decl`), the base of a field chain (`p.x` reads `p`), the receiver of a member or callable call (`p.sum()`, `c(5)`), a capture in a lambda's capture list, and anything under `print` or `exit`. An assignment target is not a read.

Two places deliberately count a fake read, so the declaration survives:

```python
# visit_decl: a value that may print keeps the declaration
if any(contains_call(value) for value in values):
    self.read(node)

# visit_assign: same for the variable being assigned
if contains_call(node.value):
    self.read(node.decl)
```

`visit_lambda` needs care. A lambda's captures do not live in the statement list: the checker moved them into a lowered `DeclNode` stored on the node. So the visitor walks `node.declaration`, where each capture is a real `VarNode` pointing at the captured variable. Without that, `i32 k{5}` captured by a lambda would look unread and be deleted.

**`Pruner`** takes the ids to remove and rebuilds statement lists instead of deleting while iterating:

```python
kept = []
for statement in block.statements:
    if self.is_dead(statement):
        continue
    self.prune_statement(statement)
    kept.append(statement)
block.statements = kept
```

`is_dead` covers a `DeclNode`, an `FnNode`, and an `AssignNode` whose `decl` is dead. `prune_statement` recurses into `if`/`else` blocks, `while` bodies, function bodies, struct methods and lambda bodies, so a dead local anywhere is reached. Blocks that end up empty stay, because their condition still runs.

It also does one thing the task did not ask for: `drop_dead_lambda_structs` filters `program.generated_structs` down to lambdas still in the tree. When a function is removed, a lambda declared inside it would otherwise leave a `lambda.helper_call` definition in the `.ll` with nothing to call it.

**`remove_unused(program)`** is the loop, and it now drives both tasks in one pass:

```python
dead  = {id(d) for d in counter.declarations if counter.reads[id(d)] == 0}
dead |= {id(f) for f in counter.functions    if counter.calls[id(f)] == 0}
if not dead: return program
Pruner(dead).prune(program)
```

It repeats because removal feeds removal: a removed initialiser can hold the last read of another variable, a removed body the last call of another function. It terminates because every round that does not stop removes at least one declaration or function, and the tree is finite.

**Argument handling.** The old `main` accepted one fixed order. Now `parse_arguments` separates flags from paths, so `--remove-unused` works first, last or in between, and an unknown `--option` is reported instead of being read as a filename. `--ast` still prints the parse tree and skips the checker, so it ignores the pass; `--ast-checked` prints the tree after it.
