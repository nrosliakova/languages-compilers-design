## 2. What this practice means, simply

### A member function is a function belonging to an object

You already support something like:

```txt
fn square := (i32 x) -> i32
{
    exit x * x
}
```

Now a function can live inside a struct:

```txt
struct Point
{
    i32 mut x
    i32 mut y

    fn d2 := () -> i32
    {
        exit x * x + y * y
    }
}
```

Then:

```txt
Point p{3, 4}
i32 result{p.d2()}
exit result
```

Here, `x` means **this particular point’s `x`**, and `y` means **this point’s `y`**.

### The hidden argument is the main idea

Although the user writes:

```txt
p.shift(2)
```

the generated LLVM function behaves conceptually like:

```txt
Point_shift(address_of_p, 2)
```

That address is essential. It lets `shift` change the original point rather than a copy. The assignment calls this hidden object argument `this`, but your language does not expose that name to users.[^https://app.notion.com/p/3fb73e86a4208059a474c2c542460c17]

### Mutation is checked separately

A method is mutating when it changes its object’s fields, directly or through another mutating method.

```txt
Point p{3, 4}
i32 a{p.d2()}
```

Allowed: `d2()` only reads.

```txt
Point p{3, 4}
i32 b{p.shift(1)}
```

Rejected: `p` is not `mut`.

For `c.center.shift(1)`, **both `c` and `center` must be `mut`**.[^https://app.notion.com/p/3fb73e86a4208059a474c2c542460c17]

### 2. Update how function bodies are checked

    def visit_fn(self, node, owner=None):
        params_frame = {}
        for param in node.params:
            params_frame[param.name] = param

        saved_scopes = self.scopes
        saved_function = self.function
        saved_struct = self.current_struct

        if owner is None:
            self.scopes = [params_frame]
        else:
            fields_frame = {
                struct_field.name: struct_field
                for struct_field in owner.fields
            }
            self.scopes = [fields_frame, params_frame]

        self.function = node
        self.current_struct = owner

        try:
            node.body.accept(self)
        finally:
            self.scopes = saved_scopes
            self.function = saved_function
            self.current_struct = saved_struct

**Why this works with your existing code:**

```txt

    parameters,
    local variables
]
```

Searching backward gives locals priority over parameters, then fields.

Also, we **replace** the surrounding scopes temporarily. That prevents methods from seeing top-level variables.
